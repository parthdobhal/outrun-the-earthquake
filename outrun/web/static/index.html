Does it really work?

Runs quakes the server has never seen, from a separate set of random seeds, and shows how far off it was.

How it works

  1. Two waves

    An earthquake sends out two waves. The P-wave travels at about 6 km/s and shakes gently. The S-wave travels at about 3.5 km/s and brings the strong shaking.

  2. Phones report

    Phones near the quake feel the P-wave first and send a tiny report: their rough area (a 2 km square) and the time.

  3. The server works it out

    The server never sees the earthquake. From the report times alone it works out where and when it started, like telling where thunder came from by when people heard it. It ignores reports that don't fit (bumped phones), and checks that phones near its answer aren't silent.

  4. Alert

    Once at least K reports agree, it sends an alert. Messages travel much faster than the S-wave, so places farther away get seconds of warning.

  5. Warning time

    Warning = when the S-wave arrives − when the alert arrives. Close to the quake that is zero or less: the no-warning zone.

Everything here is simulated: invented towns, simulated phones, a uniform crust, one moderate earthquake. See the project's ASSUMPTIONS.md for every assumption.
